# Обновление для NeuroCasper — что это и как применить

15 файлов: 8 изменены, 7 новых (список ниже). Заменяют не по одному —
перетаскиваете всю папку целиком одним действием, GitHub сам разложит по
нужным путям.

## Как применить (без git и терминала)

1. Откройте github.com/WZCasper/NeuroCasper в браузере.
2. **Add file → Upload files.**
3. Откройте эту папку у себя в проводнике/Finder и перетащите **всё, что
   внутри неё** (не саму папку целиком) в окно загрузки на GitHub —
   вложенные папки (`.github`, `src`, `migrations`) перетащятся вместе со
   своим содержимым, пути сохранятся сами.
4. Внизу страницы: сообщение коммита (например «Kick в README, тесты,
   защита от гонки постов, CI») → **Commit directly to the main branch** →
   **Commit changes**.
5. Если бот уже задеплоен и у него есть реальные данные — после коммита
   зайдите в **Actions → «4) Add live-post uniqueness constraint to D1» →
   Run workflow** (разовая задача, безопасно запустить повторно). Если бот
   ещё ни разу не деплоился — этот шаг не нужен, новая защита уже встроена
   в `schema.sql`.

## Что изменилось — коротко

- **README.md, .dev.vars.example** — Kick был полностью реализован в коде,
  но нигде не упоминался в документации; теперь есть везде, включая
  отдельный раздел «Kick» с его особенностями.
- **schema.sql, migrations/002_add_live_post_unique_constraint.sql,
  src/lib/publish.ts** — защита от дублирующегося поста в Telegram, если
  два события «в эфире» для одного стримера (например, вебхук Kick и
  проверка YouTube/TikTok по расписанию) обработаются почти одновременно.
- **src/handlers/telegram.ts** — текст `/start` теперь тоже упоминает Kick;
  выбор между YouTube/TikTok сделан явной проверкой вместо молчаливого
  «иначе — TikTok» (сейчас работало правильно, но было хрупко на будущее).
- **src/lib/*.test.ts (новые файлы), tsconfig.test.json, package.json,
  package-lock.json** — автоматические тесты (`npm test`, 23 теста), в том
  числе по-настоящему подписывающие и проверяющие вебхук Kick локально
  сгенерированным RSA-ключом — раньше этот код не проверялся вообще никак.
- **.github/workflows/ci.yml (новый)** — проверка типов и прогон тестов на
  каждый push и pull request, до деплоя.
- **tsconfig.json** — тестовые файлы (`*.test.ts`) исключены из проверки
  типов воркера; у них свой `tsconfig.test.json`, потому что тесты бегают
  под Node, а не в среде Cloudflare Workers.

Полное объяснение каждого пункта — в самом README.md (особенно разделы
«Kick» и «Известные ограничения»).
